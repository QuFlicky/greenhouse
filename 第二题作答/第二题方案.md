# Greenhouse OS 一期方案：番茄水肥计划执行与复核闭环

## 1. 业务目标与一期取舍

我建议先以番茄一个灌溉分区为试点，建立“批次阶段目标—批准水肥计划—现场执行—结果复核—工艺决策”的闭环。目标是让团队知道：今天为什么这样灌溉，实际做了什么，偏差由谁处理，下一版计划依据是什么。

待验证的业务假设是：批准计划、实际执行和异常处置可能缺少可对应的记录，交接依赖口头沟通。这不是已知现场问题。试点先建立未核对事件数量、异常处理时间、每班记录耗时及计划修订暂停时长的基线，再评价收益，不承诺增产或节水幅度。

已知事实来自题目：番茄是首期示范作物；Greenhouse OS 是生产决策与协调层；现场控制器承担实时执行、安全保护和断网自治；具体设备能力待逐项确认。

本方案假设番茄采用基质滴灌，存在水肥控制器及可识别的灌溉分区。选择水肥闭环，是因为它能在一个分区内连接批次工艺、日常作业、设备反馈和人工决策，并形成频繁发生、可核对的业务记录。若现场最主要痛点不在此，或设备改造代价过高，应调整优先级或采用人工派工。

一期做批次与分区关联、工艺和观察方案版本、日计划审批、执行记录、异常责任与处置、证据追溯。暂缓全场排产、多作物通用优化、自动调肥、机器人协同、完整数字孪生和展示系统。

与其他业务的必要联系：从定植交接取得品种、株数、时间、基质和批次身份；读取气候等相关条件作为工艺适用性依据；将水肥记录关联批次，供后续采收质量复盘使用。商品规格和产量目标由种植负责人转为阶段工艺，不由后端直接换算成 EC 或灌溉量。

## 2. 职责与最小实现

| 参与方 | 责任 |
|---|---|
| 生产负责人 | 确认批次目标、人员安排和试点范围 |
| 种植负责人／当班值班人 | 批准工艺、观察方案和计划，处理偏差，决定是否补灌及如何恢复 |
| 巡检／操作人员 | 采样、核实现场、领取和执行人工任务、记录手动操作 |
| Greenhouse OS | 计划与审批、约束检查、派发、结果核对、异常流转和审计 |
| 水肥控制器及现场自动化 | 实时调节、资源仲裁、安全互锁、执行入口检查和本地运行 |

人员可以兼任，但每班必须明确异常责任人及升级联系人。平台不逐秒控制阀门，不绕过现场保护。

后端一期采用模块化单体即可：业务接口与关系数据库保存版本、审批和状态；事务性待发送记录与后台任务负责可靠派发；设备适配层转换协议；原始回报与状态变更留痕。消息重复由业务标识处理，不把消息系统的可靠投递等同于物理执行恰好一次。模拟器、历史回放和影子运行用于后续联调验证，本答卷不实现代码或实验。

## 3. 农业调研对设计的影响

调研日期：2026-11-03。以下依据支持管理原则，不证明任何控制器接口能力。

| 判断与依据 | 适用范围及设计后果 |
|---|---|
| UF/IFAS HS1274 指出，基质持水能力、植株生长和环境影响灌溉安排，并讨论供液与排液观察。[资料 PDF](https://edis.ifas.ufl.edu/publication/HS1274/pdf) | 该资料主要面向佛罗里达自动化有限的无土栽培生产者。采用其“按条件管理”的原则；工艺绑定基质、生育阶段和环境条件，不照搬次数、用量。 |
| 同一资料明确区分佛罗里达与加拿大等较冷地区的营养液浓度、灌溉和排液指导。 | EC、排液范围及时间窗由本项目种植负责人确认；地区经验不能直接成为本地控制阈值。 |
| 阿拉巴马推广资料讨论番茄水质、EC/pH 及分开配置母液以避免沉淀。[原文](https://www.aces.edu/blog/topics/crop-production/greenhouse-tomato-production/) | 记录目标配方不等于证明实际配方正确。平台关联现场程序配置摘要与母液准备／更换确认；不凭 EC 达标宣称配方完全正确。 |

已读取上述 PDF 与阿拉巴马页面正文。检索还发现 UF/IFAS HS169 和 Penn State 水质资料，但直接访问分别出现重定向和访问限制；不将它们作为独立验收依据。有关 EC 不能识别具体离子组成的进一步核查，可补充可访问原文并请种植负责人确认；当前不据此启用自动调肥，故该缺口不阻止记录与人工审批闭环。

观察方案由种植负责人批准，至少包含指标、采样位置及覆盖范围、方法、时间范围、采样频率、有效数据要求、偏离判据和复核条件。“持续偏离”必须落实为该方案中的判据。未确认前只记录并提交人工判断，不自动宣告工艺异常。单点采样不能证明全分区正常；排液观察关联一个时间范围及事件集合，不强行归因于单次灌溉。

## 4. 每日业务流程

1. 种植负责人查看上日执行偏差、观察结果、当前阶段与环境，选择适用工艺，形成当日计划。批准内容包含事件安排、供液目标、现场程序映射及有效期。
2. 平台检查必要配置、批次分区、现场能力和异常分级；审批后参数不可原地修改。自动模式整日日程部署到控制器，控制器逐次执行并返回记录；人工模式生成可领取的作业单。
3. 巡检人员按观察方案采样，控制器提供逐次执行记录，平台分别核对执行符合性与观察证据。
4. 例如供液符合计划而观察指标触发复核条件：巡检人员检查采样方法和仪表，种植负责人结合基质、作物与供液情况决定维持、调整或继续观察。需要调整时进入暂停修订流程。
5. 新计划运行后按其观察时间范围再次复核，形成有依据的工艺决策记录。

新一天计划未获批时，提前提醒并升级到值班人；不得未经授权复制昨日计划。没有明确责任人、事件窗口和运行上限，不启用自动执行；缺少供液容差不能自动判定符合，缺少观察方案不能自动判定观察通过。

## 5. 对象、状态与接口语义

| 对象 | 必要字段 | 状态／语义 |
|---|---|---|
| 批次与工艺 | 批次、分区、品种、阶段、基质；工艺版本及适用条件 | 工艺须经批准且适用于当前批次 |
| 日计划版本 | 计划 ID、版本、事件集合、内容摘要、审批人及依据快照、最晚部署时间、执行授权截止时间 | 草稿、待审批、已批准、待复核、作废；批准不代表现场生效 |
| 部署与现场队列 | 部署 ID、计划版本、队列摘要、控制代次、现场确认时间 | 未确认、已保存暂停、自动运行、暂停中、人工接管、状态未知 |
| 灌溉事件 | 事件 ID、分区、开始窗口、目标量 L、程序配置摘要、最长运行秒数、最大供液 L、硬停止时间 | 未开始、启动中、执行中、完成、中断待核实、错过窗口、替换、取消 |
| 执行事实 | 事件 ID、实际程序、起止时间、实际量及计量来源、设备启动标识、原始记录 | 执行符合／偏差／证据不足；迟到记录追加，不覆盖原始事实 |
| 观察与工艺决定 | 观察方案版本、样本时间位置、指标与单位、有效性、覆盖范围；负责人决定 | 观察待补充／未发现偏差／发现偏差；工艺维持／调整／继续观察 |
| 异常与人工任务 | 关联事件、责任人、期限、升级人、决定；任务领取人、开始、完成、交接记录 | 处置状态与历史事实是否查明分开；失联不自动释放已开始任务 |

事件内容不可变。未开始且内容不变的 E3 可跨计划保留 ID；改变参数或窗口产生 E3b，记录替代关系并使 E3 失去调度资格。代次属于部署及恢复授权，不属于事件内容。未知或完成事件不能重新部署以触发重跑；补灌是关联原异常的独立事件。

接口例：部署请求 D3 携带 P/V3、队列摘要 H3、控制代次 18、现场作业序号 52、程序配置摘要、审批 ID 和有效期。现场只有在暂停稳定状态且这些前置条件匹配时才保存，返回“已持久化、仍暂停”。恢复授权 S3 绑定 D3/H3、代次 18、审批及快照、最晚消费时间；现场保存其消费结果。通信尝试 A1、A2 不改变 D3 或事件身份。同操作编号不同内容拒绝；相同内容重试查询或返回原结果。

实际程序内容、母液组成不能完全自动证明时，由指定人员确认并标明证据边界。只有程序编号且内容可被修改时，不得宣称配方一致。

## 6. 最终执行与恢复规则

一期所有修订均先暂停：禁止后续启动，等待当前事件完成或由现场明确停止，取得稳定快照后审批、部署、恢复。没有运行中替换的另一套规则。

每次新暂停周期，包括普通修订、人工接管和重启恢复，都持久化新的控制代次。暂停请求重试不得反复增加代次。持久化“暂停中／接管中”与事件启动在现场互斥；过程中重启不得恢复自动。无法可信恢复持久状态时禁止启动。旧部署和恢复请求因代次不符失效。

审批绑定计划摘要、控制代次、现场作业序号、已核对证据版本和配置摘要。相关人工作业、配置变化或改变供液结论的迟到证据使待部署计划进入复核；普通遥测仅在超出审批适用条件时触发复核。现场部署和恢复均检查其可见的前置条件。关键证据若在恢复授权发出后才到达，平台请求暂停并报告结果未确认，不能承诺撤回已发生动作。

恢复授权绑定确切部署与摘要、代次、审批、快照和有效期，且消费结果持久化。部署只允许在新的暂停周期内进行，避免旧启动授权启动新队列。现场在受理和每次启动时检查对应有效期；窗口内可等资源，错过窗口不补执行。最晚开始时间不等于停止时间，已开始事件仍受运行上限和硬截止约束。时钟不可靠时禁止新自动启动。

控制单元重启后整队暂停。启动前须在实际执行边界持久化启动事实；中断供液无法查明时不从头重跑，也不自动续灌。网关记住编号但下游只接受无身份启动脉冲，不足以满足该契约。

异常分级：控制模式不明、配置不符、持久状态或时钟不可信、保护故障属于阻断项；历史供液未知可由种植负责人作出明确处置、接受不确定性后批准新作业；观察待补充按已批准方案决定是否阻断，不能一概放行或阻断。

核实期限和升级规则须上线前确认，并在下一事件前留出决策时间。无法查明可以“处置结束、历史事实未知”。日计划在所有事件不可再调度且异常已有决定后业务关闭，另记事实完整性；迟到证据追加并复核后续决策，不重新激活旧队列。

## 7. 贯穿异常案例

V1 的 E1 完成、E2 启动。平台准备修订，请求暂停并形成后续部署 R2；R2 发出后失联。现场人员接管进入新代次，确认队列暂停和当前输出状态，领取并执行人工补灌 M1。R2 随后迟到，因旧代次被拒绝；若它此前已生效但回执丢失，新接管也会暂停其队列。

控制器重启后保持整队暂停。恢复连接后核查实际队列及摘要、代次、当前输出、逐次执行记录、M1、配置和未完成补偿决定。E2 迟到记录与 M1 均保留；若显示可能重复供液，负责人评估后续安排，不自动补偿第二次。无法确定的量继续标为未知。

负责人依据已核对事实或明确接受的不确定性批准剩余计划 V3；现场检查快照、保存暂停队列，再消费绑定 V3 的恢复授权。下一次只允许执行新授权队列中仍在窗口内的事件。

仅网络失联且现场仍自动运行时，执行有效本地策略；已人工暂停则由现场人员保障，不假定自动恢复；模式未知明确显示未知。网络和人员均不可达且策略到期时，本方案不能保证继续灌溉。

## 8. 准入、人工降级与待确认项

优先验证现有设备的等价能力，不要求字段同名。有限适配用于单位、程序映射及记录接入；执行入口互锁、持久代次、重启保护不能由普通网关虚构。缺少关键能力或补齐成本过大，选择人工派工。

人工操作前确认分区已有自动日程、控制权及当前输出，避免重复供液；无法确认时不得直接按平台任务补灌。任务须领取、登记开始，交接不清先核实，不能自动重新派发。现场控制器统一仲裁共享资源；做不到时，独占试点须禁用冲突队列并约束其他入口，只有口头安排则限于现场监督模式。

| 待确认条件 | 谁提供什么 | 答案变化的后果 |
|---|---|---|
| 栽培与工艺 | 种植负责人提供基质、阶段、配方、窗口、容差、观察方案 | 若土培，重做工艺与观察参数；记录审批主线保留 |
| 执行入口能力 | 自动化及供应商提供程序映射、日志、接管和重启行为并联调 | 不满足契约则人工派工，不承诺无人值守 |
| 资源与值班 | 项目人员确认共享设备、控制入口和到场保障 | 无可靠仲裁或保障则缩小自动化范围 |

若暂停经常导致错过窗口，或审批负担不能满足现场节奏，应根据试点数据重新评估修订方式与自动化范围，不能只要求人员加快审批。

AI 为可选辅助，仅生成附输入证据和版本的待审核建议；数据或计划依据变化须复核。无模型仍可依靠批准规则与人工流程运行。

## 9. 验收推演

以下是验收计划，未实际执行。先用模拟器与故障注入验证状态，再以受监督联调验证现场契约。

| 前置条件与事件 | 预期结果及证据 |
|---|---|
| 正常计划与观察 | 批次可追到审批、事件、实际程序与计量、采样及工艺决定；执行与观察分别判定 |
| 受理后回执丢失，重发同编号 | 内容相同返回原结果；内容不同拒绝。独立计量或现场动作观察能辨别重复供液，不能只看同源日志 |
| 暂停与事件启动竞争，随后重启 | 先启动的事件被纳入接管；暂停成立后无新事件启动；重启整队暂停 |
| 接管后旧部署／恢复请求迟到 | 因代次不符拒绝；现场队列和物理输出未因旧请求改变 |
| 启动中或执行中断电 | 中断事件不重跑，后续队列暂停；累计供液证据不足如实标记 |
| 人工补灌后迟到回报 | 两份事实保留，复核后续计划，不自动重复补偿；人工任务无重复派发 |
| 资源忙超过开始窗口 | 事件标记错过，不恢复补发；已有运行受上限约束 |
| 采样缺失或配置不符 | 前者按批准观察规则处理，后者阻断；没有证据不得判定全部通过 |

人工模式只验收计划授权、作业协调、记录和处置闭环，不承诺设备级去重。试点统计记录成本、异常时长、未核对数量和暂停影响；农业收益需后续合适的生产对照，不能由软件联调通过推出。
